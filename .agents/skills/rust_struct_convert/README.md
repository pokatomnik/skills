# JSON to Rust Structs Skill

Этот вспомогательный навык (skill) предназначен для автоматического преобразования примеров JSON-документов в лаконичные, идиоматичные и готовые к использованию структуры данных на языке Rust с использованием библиотеки `serde`.

## Как это работает (Использование)

LLM, использующая данный навык, выступает в роли ведущего Rust-разработчика. На вход подаются две сущности:
1. **Пример JSON-документа**, структуру которого необходимо описать.
2. **Назначение (цель) структуры** (например, `User profile response` или `Payment gateway webhook`), чтобы сгенерировать правильное семантическое имя для корневой структуры.

### Ключевые особенности генерации:
* **Строгий контракт вывода**: Навык возвращает **только чистый исходный код Rust** без разметки Markdown (без тройных бэктиков ` ``` `), пояснений, комментариев и лишнего текста. Результат сразу готов к копированию в проект или к компиляции.
* **Именование по правилам Rust**:
  * Структуры именуются в `PascalCase` на основе контекста (например, `UserProfile`, `PaymentMethod`), избегая общих названий вроде `Root`, `Data` или `Response`.
  * Поля автоматически преобразуются в `snake_case`. Если имя ключа в JSON содержит неподдерживаемые символы, дефисы или записано в `camelCase`, генерируется атрибут `#[serde(rename = "...")]`.
  * При совпадении ключа с зарезервированным словом Rust (например, `type` или `ref`), поле переименовывается с добавлением подчеркивания в конце (`type_`), сохраняя оригинальное имя в `serde(rename)`.
  * Если большинство полей используют camelCase, применяется `#[serde(rename_all = "camelCase")]` на уровне всей структуры.
* **Типизация**:
  * Строки -> `String`
  * Целые числа -> `i32` (по умолчанию)
  * Дробные числа -> `f64`
  * Булевы значения -> `bool`
  * Null-значения -> `Option<T>`
  * Массивы -> `Vec<T>`
  * Объекты -> вложенные структуры (или `HashMap<String, T>`, если ключи динамические/произвольные)
* **Атрибуты**: Все структуры получают деривацию: `#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]`.
* **Публичность**: Все структуры и поля помечаются ключевым словом `pub`.

## Пример использования

### Входные данные

```text
JSON:
{
  "userId": 101,
  "profile": {
    "firstName": "John",
    "lastName": "Doe",
    "middle_name": null
  },
  "roles": ["admin", "billing"],
  "type": "internal"
}

Structure purpose:
UserSessionInfo
```

### Результат работы навыка (вывод)

```rust
#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct UserSessionInfo {
    pub user_id: i32,
    pub profile: UserProfile,
    pub roles: Vec<String>,
    #[serde(rename = "type")]
    pub type_: String,
}

#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct UserProfile {
    pub first_name: String,
    pub last_name: String,
    #[serde(rename = "middle_name")]
    pub middle_name: Option<String>,
}
```

## Ограничения навыка

* Не используются ссылки (`&str`) и параметры времени жизни (lifetimes) — все данные владеемые (owned).
* Числовые типы жестко ограничены `i32` и `f64` (размерные типы вроде `u64`, `usize` или `i64` не используются, если это не запрошено явно).
* Не генерируются методы сериализации/десериализации, тесты, примеры кода или `impl`-блоки.
